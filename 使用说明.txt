LATIC 询价协作系统（网页端）使用说明
====================================

一、系统用途
------------------------------------
本系统用于国内团队共同处理询价任务：管理员上传并下发询价单，员工共同查看和填写产品信息，管理员审核后导出已填写的询价单。系统还可以管理个人模板、供应商报价、附件和生成文件。

当前版本是局域网测试版。MySQL 和网页服务运行在一台“服务器电脑”上，其他员工电脑通过浏览器访问服务器电脑的局域网地址。当前不需要安装 Electron 应用，也不需要让员工电脑直接连接 MySQL。


二、使用前的准备
------------------------------------
1. 准备一台长期运行的 Windows 电脑作为服务器电脑。
2. 服务器电脑和员工电脑连接同一个局域网（同一个路由器、公司网络或 VPN）。
3. 服务器电脑安装 Node.js 环境，并在项目目录安装依赖。
4. 服务器电脑安装并启动 MySQL 8.x。
5. 确认项目文件夹完整，例如：
   C:\Users\Latic\Desktop\code\rfq-collaboration-test
6. MySQL 的 3306 端口只供服务器电脑本机使用；员工电脑只访问网页服务的 3210 端口。

如果是从一台全新的电脑开始，建议先用管理员 PowerShell 执行：
   cd C:\Users\Latic\Desktop\code\rfq-collaboration-test
   npm install


三、第一次配置数据库（仅服务器电脑操作）
------------------------------------
1. 确认 MySQL 服务已经启动。当前安装脚本使用的服务名是：
   LATICMySQL84
2. 如果还没有安装项目专用 MySQL，可以用“管理员身份”打开 PowerShell，在项目目录执行：
   Set-ExecutionPolicy -Scope Process Bypass
   .\server\scripts\install-mysql-local.ps1
3. 安装脚本会创建数据库、应用账号和服务器配置文件。执行完成后，重要文件包括：
   server-data\config.json
   server-data\mysql-root-credentials.txt
4. 如果 MySQL 已经安装，但项目还没有配置，执行：
   npm run server:init
5. 初始化时依次填写：
   MySQL 地址：通常为 127.0.0.1
   MySQL 端口：通常为 3306
   MySQL 管理员账号：通常为 root
   MySQL 管理员密码：填写安装 MySQL 时设置的 root 密码
6. 初始化成功后，不要删除 server-data 文件夹。该文件夹保存数据库连接配置、上传附件和服务器日志。

注意：npm 命令必须在项目目录中执行，不能在 C:\Windows\System32 中执行。


四、启动服务器网页
------------------------------------
推荐方式：
1. 双击项目根目录的 start-web.bat。
2. 脚本会启动网页服务器并打开浏览器。
3. 本机访问地址通常是：
   http://127.0.0.1:3210

命令行方式：
1. 在项目目录打开 PowerShell。
2. 执行：
   npm run server
3. 看到“服务器已启动”或类似提示后，浏览器访问：
   http://127.0.0.1:3210
4. 关闭网页服务时，在运行 npm 的窗口按 Ctrl+C。

服务器电脑需要保持 npm run server 窗口和 MySQL 服务运行，员工电脑才能访问系统。


五、让员工电脑进入系统
------------------------------------
1. 在服务器电脑上查看启动窗口打印的局域网地址，通常类似：
   http://192.168.1.100:3210
2. 如果窗口没有显示地址，可以在服务器电脑 PowerShell 执行：
   ipconfig
   查找当前网络适配器的 IPv4 地址。
3. 在员工电脑浏览器中输入：
   http://服务器电脑局域网IP:3210
   例如：http://192.168.1.100:3210
4. 员工电脑不要填写 127.0.0.1。127.0.0.1 代表员工自己的电脑，不是服务器电脑。
5. 如果打不开页面，在服务器电脑防火墙中允许 Node.js 或 TCP 3210 入站连接，并确认两台电脑在同一网络。


六、第一次登录和账号角色
------------------------------------
1. 团队第一次打开系统时，只由负责人创建一次“初始管理员”。
2. 在登录页选择“管理员入口”，点击“我是负责人，创建初始管理员”。
3. 填写管理员姓名、账号和密码，完成创建。
4. 其他员工不要再创建管理员，选择“普通员工入口”，点击“我是员工，等待负责人创建”。
5. 管理员登录后，在“员工账号管理”中查看、启用或停用员工账号。
6. 员工可在登录页选择“注册普通员工账号”，注册后等待管理员启用。

角色说明：
- 管理员：管理账号、上传和下发询价单、审核、导出、查看资料和数据库页面。
- 经理：可管理和审核任务，具体权限以页面显示为准。
- 采购员：查看任务、填写产品数据、上传附件和保存个人模板。
- 查看者：主要用于查看，不负责编辑核心数据。


七、管理员下发询价任务
------------------------------------
1. 管理员登录后进入“共享询价任务”。
2. 点击“上传并下发询价单”。
3. 填写任务名称（不填时使用文件名）。
4. 可填写任务编号、国家、请求人、截止时间等信息（以当前页面字段为准）。
5. 勾选需要重点负责的员工。重点负责人只是提醒和标记，不会阻止其他员工查看或填写。
6. 选择上级发来的 Excel 询价表。
7. 点击“选择 Excel 并下发”。系统会保存原始文件并尝试识别表头和产品明细。
8. 下发成功后，任务会出现在所有员工的“共享询价任务”列表中。
9. 如果系统提示无法识别明细，先检查 Excel 是否有清晰的表头和产品行；原始文件仍会保存在“资料中心”。
10. 一个 Excel 文件可以包含多个工作表，也可以在同一工作表中按“表头—产品明细”的方式连续放置多个表格。系统会逐个识别这些表格并合并为同一个询价任务；导出时会按原工作表和原表头位置分别写回。

如果使用“外部接收箱”：
1. 外部询价先进入“外部接收箱”。
2. 管理员检查国家、请求人、产品数量和附件。
3. 确认无误后点击“接受并下发”。
4. 不需要的询价可点击“拒绝”，填写拒绝原因。


八、员工填写共享询价任务
------------------------------------
1. 员工登录后进入“共享询价任务”。
2. 点击需要处理的任务，查看任务详情、国家、请求人、截止日期和产品明细。
3. 每一行产品可以填写：供应商、型号、含税运人民币、FOB、总价、备注等字段，实际显示字段以任务表头为准。
4. 可以使用“打开 Excel 工具录入”，先用本机模板工具整理供应商报价，再回到任务页面选择需要填入的供应商。
5. 填写后点击对应行的“保存”或“保存当前行”。不要在未保存时直接离开页面。
6. 多名员工可以同时填写同一个任务；系统会记录最后保存的内容和修改人。
7. 如发现其他员工已经修改，先点击“刷新最新数据”，再继续编辑，避免覆盖别人刚保存的内容。
8. 备注可以记录交期、付款方式、质量情况等，也可以上传图片或 PDF 附件。
9. 在“修改记录”中可以查看谁在什么时间修改过任务。

FOB 和总价说明：
- “总价”使用最终需要填写到询价单中的含税运人民币金额。
- FOB 根据项目当前业务规则计算或填写，具体计算方式以页面字段和任务要求为准。
- 如果金额显示异常，先确认汇率、发票类型和含税运人民币是否填写正确。


九、使用模板工具整理供应商报价
------------------------------------
1. 进入“我的账号模板”或模板管理页面。
2. 点击“新建模板”，输入模板名称和字段；也可以点击“导入 Excel 模板”。
3. 如果导入模板没有识别到字段，请确认 Excel 表头或模板占位符使用了清晰的字段名称。
4. 进入“字段映射”，把模板字段映射到系统字段。
5. 如果系统没有对应字段，可以使用“自定义系统字段”或“同名新增”。
6. 点击“保存映射”。没有映射的字段不会出现在数据录入区域。
7. 进入“数据录入”，选择模板，填写供应商和报价数据。
8. 美金成本通常根据含税运人民币、发票类型和汇率自动计算；填写前请确认今日汇率。
9. 保存录入数据后，生成供应商对比表。生成的文件会保存到本机，并可在资料中心归档。
10. 回到共享询价任务，点击“打开 Excel 工具录入”或选择相应供应商，把人工筛选结果填入任务。

模板是个人模板，每个员工可以不同；任务中的产品、总价、FOB、备注等共享数据仍然保存在服务器数据库中。


十、管理员审核和导出
------------------------------------
1. 员工填写完成后，通知管理员。
2. 管理员打开任务，点击“刷新最新数据”，检查每一行的供应商、FOB、总价、备注和附件。
3. 检查无误后，将任务状态改为“待审核”或执行页面提供的提交审核操作。
4. 如需修改，管理员可以继续编辑；员工也可在权限允许时继续修改。
5. 审核通过后，管理员点击“导出已填写询价单”。
6. 导出的文件会保留原始询价单的结构，并写入已确认的数据。
7. 原始询价单、生成文件、附件和版本记录会保存在服务器文件夹及数据库记录中。
8. 导出后建议在“资料中心”确认文件已经出现，再发送给上级。


十一、资料中心
------------------------------------
1. 进入“资料中心”可以查看共享询价单、报价表、供应商资料、产品资料、模板和任务附件。
2. 可以按类别筛选，也可以按文件名搜索。
3. 点击文件名或下载按钮可以下载文件。
4. 图片和 PDF 等附件保存在服务器电脑，不要求员工直接访问服务器文件夹。
5. 删除资料前请确认是否还会用于审核、追溯或后续报价。删除通常只是标记为删除，不建议直接手动删除 server-data 文件。


十二、数据和文件保存位置
------------------------------------
数据库：MySQL 数据库 latic_rfq。
配置文件：server-data\config.json。
上传附件和生成文件：server-data\files。
服务器日志：server-data\files\logs。
MySQL root 凭据记录：server-data\mysql-root-credentials.txt。

不要把 config.json、mysql-root-credentials.txt 或整个 server-data 文件夹公开上传到 GitHub、微信群或公共网盘。这些文件包含数据库连接信息和登录密钥。


十三、日常备份建议
------------------------------------
1. 每天结束后备份 MySQL 数据库。
2. 同时备份 server-data\files 文件夹，因为附件和生成的 Excel 不在数据库中。
3. 备份文件存放到另一块硬盘或受控网盘，不要只存放在服务器电脑本机。
4. 升级程序前先备份数据库和 server-data 文件夹。
5. 恢复数据前先停止 npm run server，并保留一份当前数据副本。


十四、常见问题
------------------------------------
问题：执行 npm 命令提示找不到 package.json。
解决：先执行 cd C:\Users\Latic\Desktop\code\rfq-collaboration-test，再执行 npm 命令。

问题：员工电脑显示 127.0.0.1 拒绝连接。
解决：员工电脑不能使用 127.0.0.1，应填写服务器电脑的局域网 IP，例如 http://192.168.1.100:3210。

问题：页面打不开或连接超时。
解决：确认 MySQL 服务和 npm run server 都在运行；确认防火墙允许 TCP 3210；确认两台电脑在同一局域网。

问题：服务器提示 MySQL 连接失败。
解决：确认 MySQL 服务正在运行；检查 server-data\config.json；不要随意删除数据库。账号异常时联系管理员使用项目中的恢复脚本。

问题：提示 Table doesn't exist。
解决：先重启 npm run server，让服务器执行兼容旧数据库的建表检查；不要直接删除现有数据库。

问题：提示 Incorrect arguments to mysqld_stmt_execute。
解决：重启服务器并刷新页面。当前版本已修复资料中心分页参数问题。

问题：Excel 导入失败或未识别产品。
解决：检查文件是否损坏、是否为真正的 xlsx 文件、第一行是否为表头、产品明细是否在连续行中；必要时先在模板工具中导入并配置字段映射。

问题：生成文件中金额为 0 或字段为空。
解决：检查字段映射是否保存，检查录入数据是否已经保存，再重新生成；生成前先刷新任务数据。

问题：多人同时填写后数据看起来不一致。
解决：先刷新最新数据，再编辑和保存；以修改记录中的最后保存时间为准。重要任务建议每次只由一人负责一行或一组产品。


十五、停止、重启和升级
------------------------------------
停止网页服务：在 npm run server 窗口按 Ctrl+C。
重启网页服务：重新执行 npm run server，或重新双击 start-web.bat。
重启 MySQL：在 Windows 服务中找到 LATICMySQL84，执行重新启动。
升级程序：先备份数据库和 server-data\files，再替换程序代码，执行 npm install（如 package.json 有变化），最后重新启动网页服务。

如未来部署到云服务器，只需把网页服务和 MySQL 放到云服务器，员工继续通过浏览器访问域名；当前账号、任务、资料中心和模板的数据结构可以继续使用。


十六、安全要求
------------------------------------
1. 管理员密码和 MySQL root 密码不要发到群里。
2. 只允许可信员工注册，离职员工及时停用账号。
3. 不要把 MySQL 3306 端口直接暴露到互联网。
4. 局域网测试结束后，应配置 HTTPS、强密码、定期备份和服务器访问控制。
5. 云部署时建议使用独立数据库账号、对象存储和自动备份，不要让前端直接连接 MySQL。
